# Operator local audio libraries

Local audio uses the existing catalogue, Music queue and DirectPlayer. It does not acquire media or convert playlists. Run migrations normally, including `20261110010000-create-local-media.js`, before starting the server. The default `local_media.roots = []` performs no filesystem scans. Scans are manual, not automatic at startup.

An operator can add this to their instance TOML (example only; these directories are not created or scanned by installation):

```toml
[[local_media.roots]]
id = "household-audio"
directory = "/srv/undertone/audio"
ownerId = 42
```

On Windows use a canonical absolute path, e.g. the TOML literal `directory = 'C:\Undertone\Audio'`. Use an existing account ID. A stable root ID is bound durably to its original owner and directory; changing that binding fails closed. Add a new root ID to assign another collection. Removing configuration immediately prevents that root's sources from being selected or read; historical catalogue/library records remain. Never reuse root IDs for another account.

Owners use **Library → Local audio library → Scan library**. The UI accepts neither directories nor owner IDs. `GET /api/local-media/status` lists only the caller's configured IDs and sanitized status/counters. `POST /api/local-media/roots/:id/scan` takes an empty JSON body, the `X-Local-Media-Scan: 1` header and no query parameters. Browser requests must be same-origin; forms, cross-origin requests and mismatched Origin/Fetch Metadata are rejected. Non-browser clients may omit Origin but still need JSON and the custom header. Reverse proxies must preserve the public Host and configure the existing trusted proxy protocol handling for HTTPS termination; this endpoint does not enable CORS. Both require the existing account authentication. Scans have a durable, exclusive 120-second lease. A stale scan cannot publish after a newer lease. Each attempt visits at most 10,000 entries, 2,000 audio files and eight directory levels, with a 30-second traversal/probe budget (a final probe can add at most two seconds). OS filesystem stalls and SQL time are outside that budget. Large libraries need smaller operator roots; there is no incremental traversal cursor in this version.

Supported extensions: MP3, M4A, AAC, FLAC, WAV, OGG and OPUS. Browser codec support still varies. Metadata probing uses the installed ffprobe executable with argument arrays, audio bytes on stdin, a pipe-only protocol allowlist, an 8 MiB input bound, 64 KiB output bound and two-second timeout. Unknown/invalid metadata receives an untitled track, no artist and unknown duration. Pipe probing cannot determine duration for every container; unknown-duration recordings require manual skip because the existing server end detector needs a known duration. Directory/filename fallbacks, artwork extraction and remote metadata lookups are deliberately excluded. No scan or media request writes to library directories.

Each root/relative-path key has one opaque file/source ID and one track ID. Repeated scans do not duplicate recordings; equal titles at different paths are never merged. Renaming a file creates a distinct recording. Replacing a file at the same path refreshes that path's recording and retains its track identity. Equivalent-source linking is a future explicit operation. Provenance, path keys, relative paths and file identities stay in server storage. Removing a file marks its source unavailable only after a complete scan; it does not remove tracks, tags, library links or history. Partial/failed traversal never performs the missing-file sweep. Catalogue/provenance writes and owner version bumps are one transaction; events publish after commit. Actual metadata/availability/link changes invalidate affected owners, while no-op scans and favorites do not. The imported `roomTrackVersions` fingerprint also detects changes for current/queue/pending occurrences outside libraries, including guests and other processes.

The room Add panel lists local library recordings with the existing Mix/Next controls. Source authorization is contributor-aware during candidate selection, request resolution, playback resolution/fallback and final revalidation. Adopting shared catalogue metadata does not grant another account access to local bytes. A mixed provider/local queue retains track, occurrence, contributor, mood and history identities; source fallback retains the original occurrence. Local references cannot be fed into legacy InfoExtract/URL imports as arbitrary filesystem paths.

`GET` and `HEAD /api/local-media/:sourceId` use the app's existing HttpOnly, SameSite OTT session cookie. Browsers already obtain this cookie from `/api/auth/grant`; no bearer credential is placed in a media URL. The synchronized Video contains only `local:<opaque-source-id>`, and OmniPlayer builds a same-origin URL privately for each browser. No second player/synchronization channel is added. Owner requests work outside rooms. Other readers must supply `?room=...`, have a live token session, be actively joined under that same identity, and be listening to the exact current occurrence/source contributed by the storage owner. Current `playback.play-pause` permission is required; private rooms additionally require TrustedUser or higher. These are conservative media access rules, not a change to existing room admission policy. Every request checks current state after opening the file and before emitting bytes. Logout/session expiry, leaving the room, role/grant changes or advancing away revoke subsequent reads. Bytes already buffered by a browser or an in-flight authorized response cannot be recalled.

The endpoint supports a single byte range, suffix/open-ended ranges, HEAD, 206 and 416 with correct lengths, audio-only MIME types, nosniff, no-store, same-origin resource policy and no-referrer. Multiple/malformed/overlong ranges receive 416. Aborting a stream closes its descriptor. Public opaque IDs and catalogue metadata alone grant no access. Routes return generic failures without filesystem or provider details.

Filesystem containment rejects traversal, percent-encoded names, Windows alternate streams/trailing-dot aliases, symlinks, junctions and hardlinks. Roots must use canonical paths with no symlink ancestors. Open checks canonical containment and component lstat before/after opening, compares path stat with fstat, then compares the opened descriptor's device/inode/size/mtime with the persisted index. After the asynchronous authorization check, a synchronous descriptor stat rechecks device/inode/size/mtime before headers for GET, HEAD and ranges. Streaming uses that same descriptor, never a reopened pathname. New opens of replaced files fail until rescanned. Node has no portable openat2/GetFinalPathNameByHandle API: **operator roots must be access-controlled against hostile concurrent filesystem writers**. These checks protect ordinary replacement and link races but are not an OS-enforced sandbox for an attacker who can continually rename ancestors during indexing. **Published audio must be immutable:** ingestion must finish writing a separate file, close it, then publish it by atomic rename on the same filesystem. Never truncate, append to or overwrite a published inode in place, including through another hardlink, while it can be read. An already-authorized descriptor may finish the old indexed bytes across an atomic replacement; new requests reject the replacement until rescan. Windows/filesystem sharing rules may refuse atomic replacement while the old file is open; ingestion must retry after readers finish, never fall back to in-place writes. The final stat rejects changes during authorization but is not a pinned snapshot and cannot prevent later in-place writes. Use read-only service mounts/ACLs and an ingestion process that enforces this publication contract. Case/alias and codec behavior need platform-specific production verification.

Local media is explicitly **disabled with `balancing.enabled = true`**, including the UI, indexing, owner reads and room candidates. No route loads a Redis snapshot to invent current membership, and local RoomManager state is used only in supported single-monolith deployments. Multiple monoliths serving the same database behind a separate proxy are also unsupported: use one monolith for this feature. A future cluster implementation must route authorization to the authoritative room owner and use a shared storage/trust contract. Historical nonlocal provider sources remain functional in balancer mode.

Migration up/down is transactional in SQLite and PostgreSQL SQL generation. Down removes local provenance/status tables and preserves catalogue/history records; remaining opaque local references fail closed. Tests use isolated cache directories and SQLite, real HTTP streaming, junction fixtures and safe ffprobe input. PostgreSQL runtime, real browser codec/background playback and mobile background behavior have not been validated by these implementation checks.
